# Nitro Grafana dashboards

Grafana dashboards for the publicly released Nitro components, rendered from
[`OffchainLabs/ocl-dashboards`](https://github.com/OffchainLabs/ocl-dashboards)
with the Grafana Foundation SDK. Import the JSON files via
**Dashboards → New → Import**, or provision them with your Grafana sidecar.

> This file is generated by `dashboard-manager --community` together with the
> dashboard JSON — the tables below are extracted from the dashboards
> themselves. Do not edit it here.

| File | Dashboard | Contents |
|---|---|---|
| `community-overview.json` | Nitro Overview | Landing page for the community dashboard suite: key chain health panels and links to every published dashboard |
| `nitro-detail.json` | Nitro Node Detail | Detailed nitro metrics |
| `nitro-summary.json` | Nitro Node RPC Summary | Nitro performance metrics |
| `relay-detail.json` | Relays Detail | Detailed relay metrics |
| `relay-summary.json` | Relays Summary | Relay performance metrics |
| `sequencer-detail.json` | Sequencer Detail | Detailed sequencer metrics |
| `sequencer-summary.json` | Sequencer Summary | Sequencer performance metrics |
| `timeboost-summary.json` | Timeboost Summary | Timeboost metrics |
| `validator-detail.json` | Validator Detail | Detailed validator metrics |
| `validator-streams.json` | Redis Stream Validator Overview | Validator stream metrics |
| `validator-summary.json` | Validator Summary | Validator performance metrics |

## Datasources

Each dashboard has two datasource variables; select yours in the variable bar
after import:

- **`Source`** (Prometheus-type) — serves every metric panel. Prometheus and
  Mimir both work.
- **`Loki Datasource`** (Loki-type) — only serves the optional Kubernetes event
  annotation overlays. Without a Loki datasource (or the event stream below)
  the overlays are simply empty; all metric panels work regardless.

## Expected labels

Metric panels filter on these labels, so your scrape pipeline must attach them:

| Label | Meaning | Notes |
|---|---|---|
| `cluster` | Kubernetes cluster name | Add via Prometheus `external_labels` or relabeling if you run a single cluster |
| `namespace` | Kubernetes namespace | The `namespacepattern` variable (default `arb1-.*`) is a regex over this — set it to match your namespaces |
| `job` | Scrape job | Populates the per-component job dropdowns |
| `pod` | Pod name | Standard Kubernetes service discovery label |

## Component discovery

The cluster and per-component job dropdowns are populated by these queries. The
pod-name patterns embedded in them are the naming convention your deployments
must follow — the Offchain Labs helm charts in this repository follow them by
default. The referenced metrics must be scraped for discovery to work (run
nitro with `--metrics`; the relay exports `arb_feed_*`).

| Variable | Query |
|---|---|
| `cluster` | `label_values(arb_feed_clients_current{namespace=~"$namespacepattern"}, cluster)` |
| `nitronodejob` | `label_values(chain_head_block{namespace=~"$namespacepattern", cluster=~"$cluster"}, job)` |
| `relayjob` | `label_values(arb_feed_clients_connect{namespace=~"$namespacepattern", cluster=~"$cluster", pod=~".*relay.*|.*feed.*"}, job)` |
| `sequencerjob` | `label_values(chain_head_block{namespace=~"$namespacepattern", cluster=~"$cluster", pod=~".*seq.*", pod!~".*batch.*"}, job)` |
| `tbjob` | `label_values(rpc_duration_timeboost_sendExpressLaneTransaction_success_count{namespace=~"$namespacepattern", cluster=~"$cluster"}, job)` |
| `validatorjob` | `label_values(chain_head_block{namespace=~"$namespacepattern", cluster=~"$cluster", pod=~".*val.*", job!~".*current.*|.*timeboost.*"}, job)` |

Pod panels and the restart/OOM overlays additionally need `kube-state-metrics`
(`kube_pod_container_status_restarts_total`,
`kube_pod_container_status_last_terminated_reason`) and cAdvisor/kubelet
(`container_memory_rss`, CPU) with the same `cluster`/`namespace`/`pod` labels.

## Kubernetes event overlays (optional)

The annotation toggles (K8s Warning Events, Pod Killed, Rollouts) expect
Kubernetes events shipped to Loki the way Grafana Alloy's
`loki.source.kubernetes_events` does:

- stream selector `job="integrations/kubernetes/eventhandler"` with `cluster`, `namespace`, `type`,
  `kind` and `name` labels
- logfmt lines carrying `reason` and `msg` fields

All overlays are off by default and degrade to nothing if the stream is absent.
